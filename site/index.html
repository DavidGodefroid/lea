Many agents. None of your machine.

lea runs your AI agents side by side in containers: Claude Code by default, Codex or a model of your own too. They see one projects directory and reach the internet through a proxy, never your keys or your private network.

Install with Homebrew
brew trust davidgodefroid/tap
brew install davidgodefroid/tap/lox davidgodefroid/tap/lea

Needs Docker. Then run lea in the directory that holds your projects, and keep lox run open beside it for the Locks. The whole family: brew install davidgodefroid/tap/lockfamily.

Why lea?

Agents do more when you stop approving every command, and a few of them in parallel do more than one. On your workstation both are risky: an agent runs as you, with your keys, your tokens and your network.

lea moves the boundary from the prompt to the container. What an agent can reach is fixed by the container and the proxy, not by its good behaviour.

An agent with every permission granted, on your host and in lea
PropertyOn your hostIn lea
~/.ssh, ~/.aws, ~/.kube out of reachNoYes
Private network and cloud metadata refusedNoYes
The web limited to an allowlist of public domainsNoYes
No Docker socket, no way to root on the hostNoYes
GitHub token usable, never readableNoYes
make test and docker run still workYesYes
Every agent followed from one screenNoYes

A permission prompt is a convenience; a container and a proxy are a boundary.

See what you approve

Two kinds of request wait for you, in two places. An agent’s own permission request (run this command, edit that file) shows on its row in the deck: a allows, d denies, space jumps to the next agent that needs you.

A request to a Lock (a database, a queue, files, logs, the web) is not lea’s. It waits in lox run, which you keep open in a terminal of your own, outside lea. lea runs no lox command and shows no ticket.

To stop being asked for routine steps, a grant records your decision on the host: merge a pull request, close an issue, push the agent’s own branch. lea delivery on grants the whole push, pull request and merge cycle. Teams and grants.

Highlights

  • Side by side

    Your agents in a column, the selected one’s terminal next to it. Each row shows its state, context use, branch and its own report on its task.

    Close the terminal: they keep working, and the next lea reattaches.

  • Isolated by construction

    The container sees your projects directory and a read-only allow-list of your agent configuration. No home directory, no SSH keys, no cloud credentials, no Docker socket.

  • Online, on your terms

    Egress goes through lea’s proxy, to an allowlist of public domains. Your LAN and link-local addresses are refused; lea egress allow adds a domain live, from the host only.

  • A real dev box

    make test and docker run work: agents get their own rootless Podman inside lea, under seccomp and, on Linux, AppArmor.

  • Any agent CLI

    Claude Code is the default. Codex runs too, and through it any OpenAI-compatible endpoint (Ollama, vLLM); the endpoint’s key stays in the proxy.

  • Teams of agents

    A lead starts devs and reviewers through MCP. Agents message each other, report their progress and lease the files they edit; only you change a role.

  • Wired to the Locks

    With lox add, agents reach locksql, lockmq, lockfile, locklog and lockhttp through their sockets, read-only. The consoles alone hold the credentials.

  • Signed releases

    Every release and image is signed with cosign. The installer and lea update refuse a release whose signature does not check.

Quick start

  1. Install with Homebrew (the box above). Docker must be running.

  2. In the directory that holds your projects (not a project inside it), run lea. The first run checks Docker, pulls and verifies the images, then opens the deck.

    cd ~/projects
lea

  3. In the first agent, log in once (/login for Claude Code). Press n for the next agent.

  4. When your agents need a database, a queue, files, logs or the web, add a Lock in the same directory and keep lox run open in another terminal, outside lea.

    lox add locksql
lox run

A Lock added while lea runs reaches the agents once lea restarts: lea stop, then lea.

Know the limits

Every lea container shares the host kernel, unless you put the agents on gVisor or Kata: keep the host patched. What lea gives the agents, they can read, such as their own Claude Code or Codex login.

An agent can write files your host tools would run. lea reports changes to git hooks, risky git configuration and agent settings when the last session closes.
