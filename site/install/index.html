Install · pre-release v0.15.x

Install lea

lea runs in Docker. On your machine you need Docker, the lea command and, for the Locks, lox.

With Homebrew

Install with Homebrew
brew trust davidgodefroid/tap
brew install davidgodefroid/tap/lox davidgodefroid/tap/lea

Needs Docker. Then run lea in the directory that holds your projects, and keep lox run open beside it for the Locks. The whole family: brew install davidgodefroid/tap/lockfamily.

Homebrew asks you to trust a third-party tap once, hence brew trust first. lox is the Lock Family’s hub; lea alone does not need it, its Locks do.

Upgrade with brew upgrade lea lox.

The first run

  1. Go to the directory that holds your projects, not a project inside it, and run lea.

    cd ~/projects
lea

  2. lea checks that Docker answers, pulls and verifies its images, and records the projects directory. On Linux hosts where Docker uses AppArmor, it installs its profile with sudo, once.

  3. The deck opens on a Control Tower, a lead on Claude Code that runs /lea:control-tower. Log in once (/login); the login is lea’s own, kept per projects directory, never your host’s.

  4. Press n for another agent, N for another Control Tower, ? for the keys, q to leave. The agents keep running.

LEA_PROJECTS_DIR, in the environment or in ~/.config/lea/lea.conf, wins over the working directory. lea refuses /, your home directory, a parent of it, and a directory that overlaps ~/.claude or a credentials directory.

Requirements

  • Linux, macOS, or Windows with WSL 2 (run lea from your WSL distribution).
  • Docker Engine on Linux, or Docker Desktop, running and usable without sudo; a patched host kernel (the kernel).
  • On macOS, tmux 3.2 or later (brew install tmux); the Linux release brings its own.
  • curl, tar and ssh-keygen.
  • A subscription or API key for your agent: Claude Code by default, or Codex.

lea never runs sudo itself, except once in lea init to install its AppArmor profile, on the Linux hosts that use it.

Add the Locks

The Locks keep a human between your agents and production: locksql (SQL databases), lockmq (RabbitMQ), lockfile (files), locklog (logs) and lockhttp (outbound HTTP). Each runs as a console that alone holds the credentials.

Run lox add in lea’s projects directory, then keep lox run open in a terminal of its own, outside lea (lox 0.9.0 or later).

lox add locksql      # or lockmq, lockfile, locklog
lox run

lox run starts the projects directory’s hub and locks, approves what the rules allow on its own, and asks you for the rest. A Lock is on for lea as soon as lox run runs a lock of its type there; LEA_LOCKSQL=0 (and so on) keeps one off.

A lock added while lea runs reaches the agents after lea stop, then lea: Docker cannot add a mount to a running container.

lockhttp also needs LEA_LOCKHTTP=1 in ~/.config/lea/lea.conf: its gate then sits beside lea’s proxy and every outbound request goes through it. Web requests, with LockHTTP.

Git and forges

Git over HTTPS works out of the box, with any public forge. For GitHub, give lea a token on the host, once: it stays in the proxy, and the agents’ gh and git use it without reading it.

gh auth token | lea github login
lea github status

Prefer a fine-grained token, limited to the repositories of the projects directory. For SSH, list the endpoints in ~/.config/lea/lea.conf, pin their host keys and rerun lea init: it prints lea’s own public key to add to your forge.

echo 'LEA_GIT_SSH="github.com:22"' >> ~/.config/lea/lea.conf
ssh-keyscan github.com >> ~/.config/lea/git_known_hosts   # compare the fingerprints
lea init

Without Homebrew

lea’s own installer checks the requirements, downloads the release for your platform and verifies its checksum and signature. It then links ~/.local/bin/lea and runs lea init.

curl -fsSL https://leadeck.dev/install.sh | sh
lea

It never installs on the checksum alone: without a valid cosign signature it stops. Signed releases.

From source: clone the repository and run bin/lea init, which builds lea and its images with Docker only.

Other agents

An agent runs on a provider: claude (Claude Code, the default), codex (OpenAI’s Codex CLI, in the image), or an OpenAI-compatible endpoint of your own, run through Codex.

lea new -p codex            # one Codex agent
lea config tool codex       # without the deck: your own tool in lea

LEA_PROVIDER and LEA_MODEL set the default. Endpoints such as Ollama or vLLM go in ~/.config/lea/providers, with a key file that only the proxy mounts. Providers.

Update and uninstall

A release install updates itself at most once a day: a new patch release, its signature checked, becomes active at the next lea. lea update does it now, lea rollback goes back one version, and LEA_AUTOUPDATE=0 turns it off.

lea stop --all --forget
rm -rf ~/.local/bin/lea ~/.local/share/lea-install ~/.local/share/lea ~/.config/lea
docker image ls 'ghcr.io/davidgodefroid/lea*'   # then docker image rm the ones listed

Installed with Homebrew, brew uninstall lea removes the command; lea’s data, configuration and images are removed as above.
